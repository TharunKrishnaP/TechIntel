# TechIntel Android App (APK)

A native Android app — a Capacitor WebView wrapper around the frontend with
the **offline data snapshot baked in**. It opens instantly with zero network
and no server, exactly like the installed PWA. Launcher icons (all density
buckets) and the branded `#070A18` splash are generated by
`backend/make_icons.py`.

App id: `com.techintel.live` · name: **TechIntel**

## Get the APK (no local tooling)

The **Build Android APK** GitHub Action (`.github/workflows/build-android.yml`)
builds a debug-signed APK on free hosted runners:

1. Push to `main` (or open the workflow and press **Run workflow**).
2. Open the run → **Artifacts** → download `TechIntel-Android-APK`.
3. Copy the APK to the phone, tap it, allow **Install unknown apps** for that
   source. (A `v*` tag push also attaches the APK to a GitHub Release.)

## Build it locally

Requires **Android Studio** (or the Android SDK cmdline tools) + **JDK 17**:

```powershell
powershell -ExecutionPolicy Bypass -File mobile\build_apk.ps1
```

Artifact: `mobile\TechIntel.apk`. The script runs `npm install` (first time),
`npx cap sync android` (copies `frontend/` → `android/app/src/main/assets/`),
then Gradle `assembleDebug`.

## How the pieces fit

- `capacitor.config.json` — `webDir: "../frontend"`, so the web assets bundled
  into the APK are the very same files the PWA serves.
- `android/` — the generated Android project is **committed** so CI only needs
  `cap sync` + `gradlew`, and local builds are reproducible.
- The app boots in **static mode**: the frontend probes `/api/health` on the
  Capacitor origin, gets a 404, and loads `data/*.json` from the bundle.
- Data refreshes when a new APK is built (a "refresh" action is just rebuilding
  from the current snapshot).

## When a new APK is needed

```powershell
python -m backend.export_static   # refresh frontend/data/*.json from the DB
powershell -ExecutionPolicy Bypass -File mobile\build_apk.ps1
```
